# ReMe Long-Term Memory

ReMe stores agent memory as readable, editable Markdown files with BM25 search and wikilink relationships. This skill provides six model-facing tools to interact with the ReMe memory service.

## Before Using ReMe Tools

ReMe must be running as a background service. If tool calls fail with "not running" or "not reachable", the service needs to be started:

```bash
reme start
```

The default service address is `127.0.0.1:2333`. The default workspace is `.reme/` under the startup directory.

## Available Tools

### `reme_search` — Search Memory

Search the ReMe knowledge base for relevant content. Use this **before** answering questions about:
- Previous conversations and decisions
- User preferences and conventions
- Project history and background
- Lessons learned and procedures

```
reme_search(query="how does the auth system work", limit=5)
```

Returns matching chunks with file paths, snippets, and line ranges. Use `reme_read` to get full content.

### `reme_read` — Read a Memory File

Read a full memory file by its workspace-relative path. Use after `reme_search` to retrieve complete content of a relevant result.

```
reme_read(path="digest/wiki/authentication-architecture.md")
reme_read(path="daily/2025-01-15/api-decision.md", startLine=1, endLine=50)
```

### `reme_write` — Write a Memory File

Record a new durable memory node. Use for:
- Important decisions and their rationale
- User preferences and conventions
- Project architecture documentation
- Lessons learned from debugging

```
reme_write(
  path="digest/wiki/error-handling-pattern.md",
  name="Error Handling Pattern",
  description="Standard error handling for API layer",
  content="# Error Handling Pattern\n\nWe use..."
)
```

**Do not** store secrets, API keys, or sensitive personal data unless the user explicitly requests it.

### `reme_save_memory` — Save Conversation to Memory

Distill the current conversation into daily memory cards. This requires ReMe LLM configuration (an API key). Use after a productive conversation to preserve what was learned.

```
reme_save_memory(
  sessionId="session-abc123",
  messages=[
    {"role": "user", "content": "How should we structure the API?"},
    {"role": "assistant", "content": "We should use a layered architecture..."}
  ],
  memoryHint="API architecture decision with layered approach"
)
```

### `reme_proactive` — Read Interest Topics

Read proactive topics generated by ReMe's auto_dream consolidation. These suggest areas the agent may want to bring up.

```
reme_proactive(date="2025-01-15", includeContent=false)
```

The host agent decides whether and how to mention these topics. ReMe does not take external action independently.

### `reme_dream` — Consolidate Memory

Run memory consolidation to merge daily notes into long-term digest knowledge. Requires LLM credentials.

```
reme_dream(date="2025-01-15", hint="Focus on architectural decisions")
```

## Memory Workspace Structure

ReMe organizes memory into layers:

- **`session/`** — Raw conversation source records
- **`daily/YYYY-MM-DD/`** — Lightly processed daily memory cards
- **`digest/personal/`** — Personal facts and preferences
- **`digest/procedure/`** — Procedural knowledge and how-tos
- **`digest/wiki/`** — Knowledge nodes and concepts

## Best Practices

1. **Search before answering** — Always search ReMe first when the question could relate to prior context
2. **Read before writing** — When updating knowledge, read existing files first to avoid overwriting
3. **Use stable paths** — Keep memory paths consistent so wikilinks remain valid
4. **Be selective** — Don't save every conversation; focus on durable, reusable knowledge
5. **Consolidate periodically** — Run `reme_dream` to merge daily notes into digest knowledge
6. **Cite sources** — When using memory in answers, cite the workspace paths used

## When ReMe Is Not Available

If the ReMe service is not running, tools will report a clear error. Inform the user and suggest:

```bash
reme start
```

Basic memory operations (search, read, write) do not require LLM credentials. Only `reme_save_memory` and `reme_dream` need an LLM API key configured.
